# qtim Doctor — самодиагностика

Read-only диагностика: ничего не чинит без подтверждения. Запускай при «что-то не работает», после обновления плагина или Codex, или при онбординге коллеги в проект с qtim-командой.

## Чеклист (прогони все пункты, собери в таблицу pass / warn / fail)

1. **Плагин.** `../../.codex-plugin/plugin.json` читается? Зафиксируй `version`. Не читается — плагин установлен нештатно: переустановка командами из `$qtim-update`.
2. **Charter.** `.codex/team-charter.md` существует (нет -> `$qtim-setup`); первой строкой stamp `<!-- qtim-version: X.Y.Z -->` (нет -> legacy-состояние, предложи `$qtim-update`); версия stamp совпадает с версией плагина (расходится -> `$qtim-update`); track-маркеры `qtim:track:*` парные; обязательные секции на месте (roles table, model matrix, working rules, memory layout). Для stamp 2.10.0+ model matrix обязана фиксировать team-lead `gpt-5.6-sol` + `ultra`, architect/reviewer Sol+xhigh, database/frontend/product Sol+high, testing Terra+medium, built-in explorer Luna+medium и ADR adversary Sol+xhigh/max; отсутствие -> warn с `$qtim-update`. Для PM-трека проверь между маркерами оба трека (`feature-brief.md` + полный), общий checkpoint decomposition/estimate, selective consult и vertical slicing/expand-contract с DRI и contributing roles; layer estimates + DRI synthesis обязательны для полного трека, а fast-path должен фиксировать main-thread evidence fallback без обязательного fan-out. Отсутствие при stamp 2.9.0+ -> warn, при старом stamp -> info с `$qtim-update`. Каждый charter 2.10.0+ обязан содержать отдельный обязательный ADR stress-test через clean-context Sol adversary и строку `adr-stress-test:` независимо от настройки code review. Если independent code review включён, charter обязан содержать всю canonical high-risk matrix: security/auth/tenant-scope visibility; money/billing/account state; documented domain invariants/public contracts; data-transform/destructive migrations; critical browser flows; high-risk performance/reliability; другое доказанно hard-to-rollback изменение, плюс обязательный read-only review при любом совпадении и явный low-risk skip. Неполный enabled block при stamp 2.9.0+ -> warn с `$qtim-update`; заглушку выключенного code-review gate не считай ошибкой, если ADR stress-test сохранён.
3. **Агенты.** Для каждой роли из charter (кроме встроенных `explorer`/`worker` — им свой файл не требуется): `.codex/agents/<name>.toml` существует; TOML парсится (`tomllib` при наличии Python 3.11+); `name` совпадает; первой строкой `# qtim-version: ...`; нет `{{...}}` и plugin-internal путей. Если independent code review выключен, в ролях не должно быть risk-based code-review требований, но architect обязан сохранить ADR stress-test. Для stamp 2.9.0+ проверь engine markers: architect знает `$qtim-brainstorm`/ADR filter, database/frontend/testing — `$qtim-debug-loop`, reviewer — `skipped (low-risk diff)`; для stamp 2.10.0+ architect также знает `ADR готов к независимому stress-test` и `adr-stress-test:`. Model policy 2.10.0+: exact template pairs — architect/reviewer `gpt-5.6-sol`+`xhigh`, database/frontend/product `gpt-5.6-sol`+`high`, testing `gpt-5.6-terra`+`medium`; catalog-supported user override допустим; ровно одно поле или `model = "inherit"` -> fail. Отсутствующая pair у stamp 2.9.0 означает прежний inheritance default и требует `$qtim-update`; пары qtim 2.7/2.8 и старые `gpt-5.5`/`gpt-5.4` — legacy. Недоступный current slug -> warn и pending migration/осознанный override, не удалять pair и не угадывать alias. `ultra` или Fast в role TOML -> fail; `max` допустим только ephemeral ADR adversary, не постоянной роли.
4. **Hooks.** Отсутствие `.codex/hooks.json` — `pass`: plugin-bundled `SessionStart` / `SubagentStop` работают без project-файла. Если файл есть, проверь не только `json.tool`, но и Codex schema: корень `hooks`; event содержит массив matcher groups; каждый group — вложенный массив `hooks`; qtim handler имеет `type: command` и Windows override `commandWindows`. Top-level events, прямой handler вместо group, `type: reminder` или поле `message` -> `fail`. Распознанные qtim-копии `SessionStart` / `SubagentStop` в project layer -> `warn` как дубли bundled hooks; старый qtim `SubagentStop` с plain stdout -> `fail`, потому что событие требует JSON; qtim `PostToolUse` с plain stdout -> `fail`, потому что такой вывод игнорируется, рабочий вариант возвращает `hookSpecificOutput.additionalContext`. Напомни про trust review через `/hooks`. Не исполняй неизвестные команды и не объявляй пользовательский handler qtim-дублем только по имени event.
5. **Память.** `memory/MEMORY.md` существует; файлы, на которые ссылается индекс, существуют; `memory/epic-state.md` не содержит заведомо устаревшего «в полёте» (эпик давно завершён -> warn, предложить убрать).
6. **PM-трек** (если включён в charter). Артефакты в `docs/features/*/` имеют шапку со Status; каталог использует либо `feature-brief.md`, либо полный набор, а переход трека объяснён в истории; строки-указатели в `memory/decisions.md` ведут на существующие каталоги. Продуктовая память: создана, но не вписана в read-on-start product -> warn; не создана -> info с `$qtim-product-onboard` для существующей базы.
7. **Skills.** Bundled `$qtim-debug-loop`, `$qtim-prototype`, `$qtim-brainstorm`, `$qtim-grill` должны быть доступны из установленного плагина; отсутствие -> новая задача Codex после переустановки/upgrade, а не удаление mandatory practice. Отдельно проверь внешние skills из charter; недоступные -> warn и предложи убрать или установить.

## Вывод

Таблица: пункт · статус · что именно не так · конкретный фикс (skill, команда или правка файла).

После таблицы предложи применить **безопасные** фиксы (создание недостающего `MEMORY.md`, устаревший `epic-state.md`, распознанный qtim-дубль hooks) — по подтверждению пользователя, по одному классу за раз. Показывай diff и удаляй только qtim-owned handler, а не весь event/group с пользовательскими соседями. Миграцию версий не делай сам — отправляй в `$qtim-update`. Ничего не удаляй без подтверждения; сомнительное — только показывай.

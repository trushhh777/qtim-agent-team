# qtim Brainstorm

Разбери пространство задачи до проектирования. Выход — сырьё для design brief или ADR, не финальное решение.

## Шаги

1. **Интерпретации.** Сформулируй минимум две трактовки запроса. Если честно видна только одна, объясни почему; не выдумывай искусственную вторую.
2. **Факты — сам.** Собери из кода, `memory/`, git и доступной документации прецеденты, ограничения, задетые инварианты и конвенции. Пользователю не задавай вопрос, ответ на который лежит в окружении.
3. **Варианты.** Предложи 2-3 жизнеспособных подхода с условиями победы и трейд-оффами. Включи минимальный вариант: «что если почти ничего не делать?». Заведомо проигрышное чучело не считается альтернативой.
4. **Unknowns.** Раздели open questions, которые решает пользователь, и предположения, принятые тобой. Каждое предположение пометь и сделай обратимым. UX- или поведенческую развилку предложи разрешить через `$qtim-prototype`.
5. **Выход.** Сведи понимание задачи, evidence, варианты, затронутые инварианты, рекомендацию, open questions и предположения. Сохрани в design artifact только если workflow или пользователь просит запись.

## Anti-patterns

- Первое правдоподобное решение становится единственным.
- Факт из кода выносится пользователю как вопрос.
- Альтернатива-чучело создаёт видимость выбора.
- Предположение молча становится требованием.
- Обсуждение уходит в детали реализации до согласования смысла задачи.
